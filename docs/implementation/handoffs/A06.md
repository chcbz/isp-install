# A06 Handoff

## Scope

- Durable `commandId` dedupe with canonical fingerprinting
- Persistent ACK outbox replay on reconnect
- Cross-restart inbox recovery without duplicate execution

## Notes

- Fingerprints are computed from the resolved semantic message fields after `normalizeInboundMessage`; field order does not matter.
- The same `commandId` with a different business payload is rejected closed.
- `RECEIVED` / `STARTED` / `SUCCEEDED` / `FAILED` / `REJECTED` ACKs are persisted before send and replayed after reconnect.
- Do not run two clients for the same canonical `agentId` concurrently.
